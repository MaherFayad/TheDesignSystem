## 1.3.6 Select

Radix Select. The trigger box is the root (`data-ds="select"`, a button with
role combobox); the content is its own root carrying `data-part="content"`,
portaled into a Theme copied from the trigger's Theme (the Combobox popup
pattern). Rows reuse the ListBox row tokens (`list.row.height`, sm
`size.control.xs`, the same padding, gap, radius, weight and highlight), with
the check column on every row.

```ts
interface SelectProps extends Omit<ComponentProps<'button'>, 'value' | 'defaultValue' | 'onChange' | 'title' | 'children' | 'type' | 'dir' | 'ref' | 'disabled'> {
  items: readonly ListBoxItem[];          // as ListBox: options or titled groups
  value?: string | null;                  // controlled with onValueChange
  defaultValue?: string | null;           // default null
  onValueChange?: (value: string | null) => void;
  open?: boolean; defaultOpen?: boolean; onOpenChange?: (open: boolean) => void;
  placeholder?: string;                   // default "Choose an option" / "اختيار من القائمة"
  size?: 'sm' | 'md' | 'lg';              // default md
  shape?: 'default' | 'pill';             // default default
  invalid?: boolean; disabled?: boolean; readOnly?: boolean; required?: boolean;
  loading?: boolean; loadingLabel?: string;
  empty?: ReactNode;                      // default "No options to choose from yet."
  name?: string; form?: string;
  ref?: Ref<HTMLButtonElement>;           // the trigger, the root
}
```

Decisions:

- The trigger stamps no `data-state`; open shows as `aria-expanded`, and
  `data-state="open"` is on the content root. The contract suite reads a
  static `data-state` on an overlay root as a presentational example that
  stamps state.
- `contract.skipAxeRules: ["aria-hidden-focus"]`. While open, Radix Select
  sets `aria-hidden` on the page and traps focus in the list, so the other
  triggers cannot be reached; axe flags them by shape. A probe showed only
  the hidden Select triggers were named. The closed pages passed axe with the
  rule on before it was skipped. Dialog passes the same rule in the full
  report; I did not find why it differs.
- Radix Select has no exit presence, so the list leaves at once; the motion
  is the `menu-scale` entry only.
- Read only and loading block only the keys that open the list or choose by
  typeahead; loading describes the trigger with the loading words through a
  `hidden` span in `aria-describedby`, since the list cannot open.
- Popper position (under the trigger, as wide as it), not Radix's item
  aligned position, to match the Combobox popup.

## 1.3.9 MultiSelect

Hand built on ListBox (multiple) and Radix Popover. The root is the bordered
box; the `trigger` part inside it is the APG select-only combobox (a focusable
div with role combobox). The popup root holds a SearchField (`search`), the
ListBox and an `actions` row with two system Buttons (`select-all`, `clear`).

```ts
interface MultiSelectProps extends Omit<ComponentProps<'div'>, 'title' | 'children' | 'defaultValue' | 'onChange' | 'role' | 'dir' | 'ref' | 'className' | 'style'> {
  items: readonly ListBoxItem[];
  value?: readonly string[]; defaultValue?: readonly string[];   // default []
  onValueChange?: (value: string[]) => void;
  open?: boolean; defaultOpen?: boolean; onOpenChange?: (open: boolean) => void;
  summary?: 'tags' | 'count';             // default tags
  maxTags?: number;                       // default 3, then "+N"
  formatCount?: (count: number) => string; // default "3 selected", Arabic by Intl.PluralRules
  placeholder?: string;                   // default "Choose options"
  searchable?: boolean;                   // default: more than 8 options
  searchLabel?: string;                   // default "Search options"
  actions?: boolean;                      // default true
  selectAllLabel?: string; clearLabel?: string;   // "Select all", "Clear selection"
  size?: 'sm' | 'md' | 'lg'; shape?: 'default' | 'pill';
  invalid?: boolean; disabled?: boolean; readOnly?: boolean; required?: boolean;
  loading?: boolean; loadingLabel?: string; empty?: ReactNode;
  name?: string;                          // one hidden input per value
  className?: string; style?: CSSProperties; rootProps?: ComponentProps<'div'>;
  ref?: Ref<HTMLDivElement>;              // the trigger
}
export function defaultSelectedCount(count: number, lang: string): string;
```

Decisions:

- Tags in the trigger are drawn only (`aria-hidden`) and hold no remove
  button: a button inside a combobox is a control inside a control. The
  labels are read from a visually hidden `summary-text` written with
  `Intl.ListFormat`. Values are removed in the list or with Clear selection.
- Tab and Shift+Tab cycle inside the open popup (search, list, actions), as
  Select and DropdownMenu keep focus in their lists; Escape and Enter return
  focus to the trigger. The popup is not modal (no `aria-hidden` on the page).
- The search field and the actions sit in `<FieldContext value={null}>` so
  they never take the outer Field's id, label or error.
- The Field label's `for` cannot label a div, so the trigger is named with
  `aria-labelledby` and a click listener on the label focuses it.
- Arabic count words are white Saudi dialect, like the Combobox count
  (`نتيجتين`): `عنصر واحد محدد`, `عنصرين محددين`, `3 عناصر محددة`,
  `11 عنصر محدد`. The reviewer asked for formal Arabic (`عنصران محددان`,
  `11 عنصرا محددا`). I kept the dialect to match Combobox and documented
  `formatCount` for products in Gulf modern standard Arabic. The lead may
  rule otherwise for the whole list family.

## 1.3.10 TagField

Hand built. The root is the bordered box that wraps; tags sit in a
`role="group"` part (`display: contents`) named like the field, each `tag` a
pill with a `tag-label` and a CloseButton (`tag-remove`). With `suggestions`, the control becomes an ARIA
1.2 combobox over a ListBox with `virtualFocus` in a Radix Popover, as in
Autocomplete. Shared logic in `packages/shared/src/tags.ts`: `splitTags`,
`hasTagSeparator`, `tagKey`, `addTags` (dedupe through `normalize()`, max),
`hasTag`, `TAG_SEPARATORS`.

```ts
interface TagFieldProps extends Omit<ComponentProps<'input'>, 'size' | 'type' | 'value' | 'defaultValue' | 'onChange' | 'title' | 'ref' | 'className' | 'style' | 'children' | 'role' | 'max'> {
  value?: readonly string[]; defaultValue?: readonly string[];  // default []
  onValueChange?: (tags: string[]) => void;
  suggestions?: readonly ListBoxItem[];   // choosing one adds its label; added tags are not suggested
  max?: number;
  size?: 'sm' | 'md' | 'lg'; shape?: 'default' | 'pill';
  invalid?: boolean; disabled?: boolean; readOnly?: boolean; required?: boolean;
  removeLabel?: (tag: string) => string;  // default "Remove tag <tag>" / "حذف الوسم <tag>"
  formatRemoved?: (tag: string) => string; // default "Removed tag <tag>"
  name?: string;                          // one hidden input per tag
  className?: string; style?: CSSProperties; rootProps?: ComponentProps<'div'>;
  ref?: Ref<HTMLInputElement>;            // the native input
}
```

Decisions:

- Anatomy adds `tags` (the list wrapper) and `status` (the polite live region
  for removal, duplicates and max) to the order's parts.
- Remove buttons are `tabindex -1`: the control is the one tab stop, and
  Backspace and the arrows reach the tags, so a long tag list does not add
  ten tab stops. Pointer users press them directly.
- Pasting text with a separator adds every part; a single line pastes as text.
- No loading case: TagField fetches nothing itself.
- Read as a field by the contract suite (no trigger), like Combobox; the open
  popup was checked by a separate axe run in studio dark, desk light and
  neutral light rtl with no violation.

## Token gaps

- No `size.tag.*` or `tag-field.*` component tokens: tags use
  `size.control.xs` for height and `color.bg.overlay-10` for the fill.
- No popup width token beyond `menu.width.min`; the popups take the trigger
  width from Radix.

## Review findings

Select (2 blockers, 9 notes). Fixed: the loading words were never read (now
`aria-describedby`); the open listbox had no name (now the Field label); read
only blocked every key (now only opening keys); a separator could lead an
emptied group list; empty text now describes the list; `form` passed to the
Radix Root with a FormData test; the transparent outline only under
`:focus-visible`; border style and width through private properties; invalid
drawn heavier in forced colors. Left open: the `--_menu-*` names (see below);
`items` typed `node` in the manifest (the schema has no array type; the
description says so).

MultiSelect (2 blockers, 10 notes). Fixed: state selectors now swap
`--_multi-select-value-fg` and `--_multi-select-icon-opacity`; Clear
selection disabled when only disabled options are chosen; `aria-controls`
names the listbox; hidden inputs only for known values; the focus text, the
Ctrl+A and Escape keys and the Arabic list example corrected in the manifest;
the contrast-more tag outline repeated under `[data-contrast='more']`; the
city hint; three more tests (controlled value, disabled values kept, label
focuses the trigger). The label click fix replaces the reviewer's button
suggestion (a bare button is not allowed). Left open: the Arabic plural
register (above).

TagField (2 blockers, 10 notes). Fixed: a paste now replaces the selected
text; text past `max` stays in the control instead of being lost; tag keys
are `${index}-${tag}` so a controlled value with an exact duplicate does not
break; a pending focus move is dropped when a controlled parent refuses a
removal; hidden inputs get `form`; adds are announced once ("Added tag x");
Arabic status copy (`حذفنا الوسم`, `الحد الأعلى للوسوم: 10`) and the demo
error (`أضف وسما واحدا على الأقل`); the box padding subtracts the private
border width; the manifest says why `value` is typed string and where
Escape is documented. The reviewer found `aria-disabled` unsupported on
`role="list"`, and dropping it brings back axe contrast failures on the
faded disabled tags, so the wrapper is now `role="group"` (which supports
`aria-disabled`) and the list item roles are gone. Left open by decision:
blur keeps typed text and does not add it (noted in the manifest); Escape is
written inside the ArrowUp entry because the suite checks Escape only on
an overlay with a trigger.

## Changes needed from the lead

1. **The list family popup CSS.** `Combobox.css` says MultiSelect and
   TagField add their names to its popup selector lists. A lane may not edit
   another component's CSS, so `MultiSelect.css`, `TagField.css` and
   `Select.css` each carry the same popup block (surface, nested ListBox
   values, motion, contrast and forced colors), and each has a Desk recipe
   with the same glass. To fold them: in `packages/css/src/components/Combobox.css`
   and `packages/styles/desk/recipes/Combobox.css`, replace every
   `:is([data-ds='combobox'], [data-ds='autocomplete'])[data-part='popup']`
   with `:is([data-ds='combobox'], [data-ds='autocomplete'], [data-ds='multi-select'], [data-ds='tag-field'])[data-part='popup']`,
   then delete the popup sections of `MultiSelect.css` and `TagField.css`
   (from "the popup: the menu surface" through the popup forced colors rule)
   and the two Desk recipes. MultiSelect's popup adds `gap` and its own
   max height on the nested ListBox; keep those two rules in `MultiSelect.css`.
2. **The `--_menu-*` private names.** Anatomy rule 1 asks for
   `--_<component>-*`. DropdownMenu, the Combobox popup and these three
   popups share `--_menu-*` so one recipe shape draws every menu surface. A
   ruling in `DECISIONS.md` either way; a rename touches DropdownMenu,
   ContextMenu, Menubar, Combobox, Autocomplete and this lane.
3. **The shared popup layer.** `ComboboxBase.tsx` keeps its own
   `usePopupLayer` and this lane added the same in
   `packages/react/src/components/Select/popupLayer.tsx`. Move it to
   `packages/react/src/internal/popupLayer.tsx` and import it from
   ComboboxBase, Select, MultiSelect and TagField.
4. **Arabic count register.** Rule once for the list family (Combobox,
   MultiSelect) whether default counts are white Saudi dialect or Gulf modern
   standard Arabic.
