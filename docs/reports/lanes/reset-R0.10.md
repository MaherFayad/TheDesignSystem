`<html>` carried the same value as `#gallery-root` in every case. No console

Override order, proven on every profile above:

1. Prop: unit tests (`<Theme platform="web">` on an iPhone agent stamps web;
   `android` and `macos` likewise; a prop wins over URL, stored and device in
   `resolvePlatform`).
2. URL key: `?platform=web`, `macos`, `android`, `ios` each stamp that value
   on every profile. `?platform=windows` and `?platform=auto` are ignored and
   the device decides.
3. Stored choice: picking android in the bar stores `ds-platform=android`;
   a load with no query then stamps android, source `stored`;
   `?platform=web` still wins over the stored android. Picking Auto removes
   the key and the next load returns to the device.
4. Device: the table above.
5. Otherwise web: no device record gives web.

Server render and hydration (unit test, iPhone agent): `renderToString`
gives `data-platform="web"`; after `hydrateRoot` the element holds `ios`;
no `console.error` and no recoverable error.

## Decisions made

- `auto` is resolved with `useSyncExternalStore` (server snapshot `web`).
  Under hydration React renders `web` and then stamps the detected value once
  after mount, with no warning. In a client only render (the gallery uses
  `createRoot`) the first render already has the detected value, so a phone
  never paints one frame of web.
- A nested Theme with `platform="auto"` asks the device again, even under a
  parent with an explicit value. A nested Theme with no prop inherits.
- The client hints platform wins when it says `Android` or `iOS`; any other
  hint value falls through to the agent string.
- A Mac agent counts as an iPad only with `maxTouchPoints` above 1, as the
  contract says. Raw Chromium emulation of a touch Mac reports 1, so it gives
  web; the probe overrides `maxTouchPoints` to 5 and removes client hints to
  match what iPadOS Safari reports.
- A switch choice in the gallery bar both stores the choice and sets the URL
  key, so the address can be shared; Auto clears both.
- `?platform=auto` is treated as unknown (falls through), since step 2 only
  takes one of the four values.
