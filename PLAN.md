## 3. Architecture

### 3.1 The layers

| Layer | Shared by all frameworks | Written per framework |
| --- | --- | --- |
| Tokens | DTCG JSON, one build | Outputs: CSS variables (web), typed theme objects (React Native) |
| Look | `packages/css`: one CSS file per component, used by React and Angular byte for byte | React Native: a style function per component |
| Style packs | Token files, `style.json`, icon map, motion values | Web recipes in CSS. Native recipes in TypeScript. |
| Logic | `packages/shared`: calendar math, list filtering, toast queue, window manager, chart scales and layouts, formatters, bidi helpers. Pure TypeScript, no framework. | None |
| Behavior | The anatomy contract and the keyboard map in the manifest | Radix (React), the CDK and Angular Aria (Angular), RN Primitives (React Native) |
| Manifests, docs, checker, contract tests | One set | A code sample per framework inside each manifest |

Rules that follow from this:

- Anything that can be pure TypeScript goes in `packages/shared`, never in a
  framework package.
- React writes the component CSS. The Angular port may not change it. If the
  Angular DOM cannot match the CSS, that is a contract bug: stop, report, and
  fix the contract.
- React Native never imports from `packages/css`.

### 3.2 Runtime axes

On the web, a `Theme` component (React) or `dsTheme` directive (Angular)
stamps all axes on its own element, resolving anything not passed from the
nearest parent. Token selectors are always compounds on one element. On React
Native, a `ThemeProvider` passes the resolved theme object through context.

| Axis | Web attribute | Values |
| --- | --- | --- |
| Style | `data-style` | `studio`, `desk`, `neutral`, `liquid`, `paper`, any custom id |
| Scheme | `data-scheme` | `dark`, `light` |
| Density | `data-density` | `compact`, `default`, `comfortable` |
| Contrast | `data-contrast` | `default`, `more` |
| Platform | `data-platform` | `web`, `ios`, `android` |
| Glass | `data-glass` | `clear`, `regular`, `tinted` (only read by styles that use glass) |
| Direction and language | `dir`, `lang` | `ltr` or `rtl`, `en` or `ar` |

### 3.3 Where a difference between styles may live

| Kind of difference | Lives in |
| --- | --- |
| A value | Tokens |
| The way an existing part is drawn | A recipe in the style pack |
| A part only one style shows | An optional part, off by default, turned on in `style.json` |
| Behavior | Never in a style. It becomes a prop. |

### 3.4 CSS rules (web)

- Cascade layers, in this order:
  `@layer ds.reset, ds.tokens, ds.base, ds.recipes, ds.overrides;`
  Consumer CSS outside the layers always wins. No `!important` anywhere.
- Tokens only. No raw color, spacing, radius, font size, shadow, duration or
  z-index in component CSS. A test enforces this.
- Logical properties only. A test enforces this, with an allow list that
  gives a reason per entry.
- Only `transform` and `opacity` animate. Durations and eases come from
  tokens. Everything collapses under `prefers-reduced-motion`.
- Translucent surfaces turn solid under `prefers-reduced-transparency` and
  `prefers-contrast: more`.
- No animation library on the web. CSS transitions, `@starting-style` and the
  Web Animations API only.

### 3.5 The anatomy contract

**Web (React and Angular render the same DOM)**

- Root element: `data-ds="<component-kebab>"`.
- Parts: `data-part="<part>"` (for example `label`, `icon`, `title`, `body`,
  `footer`, `close`).
- Shared variant axes, the same names on every component, as attributes:
  `data-size` (`xs`, `sm`, `md`, `lg`), `data-tone` (`neutral`, `accent`,
  `success`, `warning`, `danger`, `info`), `data-emphasis` (`solid`, `soft`,
  `outline`, `ghost`, `link`), `data-shape` (`default`, `pill`, `square`).
- States as attributes: `data-state`, `data-disabled`, `data-orientation`,
  `data-loading`, `data-invalid`, `data-readonly`, `data-selected`,
  `data-dragging`. Never a class for state.
- No component invents another word for size, tone, emphasis or shape.
- Every interactive element comes from the system. No bare `<button>` in
  components, demos or templates outside the Button implementation itself.
- Controls are at least 24 by 24 CSS px (`size.target-min`). `lg` is 44px.

**React rules**

- React 19 style: `ref` is a prop, no `forwardRef`. Interactive files start
  with `"use client"`. No `window` access at module scope.

**Angular rules**

- Standalone components, signal inputs (`input()`), `OnPush`, safe for
  zoneless apps.
- Attribute selectors so the host element is the part itself:
  `button[dsButton]`, `[dsDialogTitle]`, `[dsDialogFooter]`. No wrapper
  elements that React does not have.
- Host bindings set `data-ds`, `data-part` and the variant and state
  attributes. Input names equal the React prop names.
- Behavior from `@angular/cdk` first (overlay, dialog, a11y, bidi, listbox,
  menu, table, drag and drop), then `@angular/aria` for the patterns it
  covers. If Angular Aria is still a developer preview, pin its version and
  import it only inside `packages/angular/src/behavior/`, so a breaking
  change stays in one folder.
- Wrap the app direction with the CDK `Directionality`.

**React Native rules**

- Same component names and the same prop names and values as React.
- There is no DOM. Each part gets `testID="ds-<component>-<part>"`. States go
  through `accessibilityState` and `accessibilityRole`, from the manifest.
- Behavior from `@rn-primitives/*`. Animation from Reanimated 4.
- Styles: a `create<Component>Styles(theme, variants)` function in
  `<Component>.styles.ts`, using `StyleSheet`. No inline color or size
  literals. A lint rule enforces this.
- Style pack recipes for native are functions in
  `packages/styles/<id>/native/<Component>.ts` that adjust the base styles.
- Touch targets are 44pt on iOS and 48dp on Android.
- Respect safe areas, the keyboard, the system font scale to 200%, reduce
  motion and reduce transparency (`AccessibilityInfo`).
- RTL through `I18nManager`. A direction change needs an app restart, and the
  language switch pattern says so.
- Glass: use `expo-glass-effect` when `isLiquidGlassAvailable()` is true.
  Otherwise render the designed fallback: a tinted solid surface with a soft
  blur where `expo-blur` is present. Never leave a plain unstyled view.

### 3.6 Token contract

Source format: DTCG JSON. Before you write the first token file, fetch the
current spec at designtokens.org. If it differs from the shapes below, the
spec wins, and you note it in `DECISIONS.md`.

```json
{
  "color": {
    "bg": {
      "surface": {
        "$type": "color",
        "$value": { "colorSpace": "srgb", "components": [0.106, 0.106, 0.106], "alpha": 1, "hex": "#1b1b1b" },
        "$description": "Darker parent of tile cards, sidebar fill"
      }
    }
  },
  "size": {
    "control": {
      "md": { "$type": "dimension", "$value": { "value": 32, "unit": "px" } }
    }
  },
  "duration": {
    "base": { "$type": "duration", "$value": { "value": 120, "unit": "ms" } }
  }
}
```

- Fluid `clamp()` values: `$value` holds the max in px, and
  `$extensions["ds.fluid"]` holds `{ "min", "max", "minViewport": 380,
  "maxViewport": 1440 }`. The CSS build emits the `clamp()`. The native build
  uses the max.
- Shadows, typography and cubic beziers use the DTCG composite types.
- CSS variable prefix: `--ds-`. Path `color.bg.surface` becomes
  `--ds-color-bg-surface`. The prefix is one constant in the token build.

**Build outputs** (`packages/tokens/build.ts`, a small script you own):

1. Layered CSS, one selector per style and scheme.
2. Typed theme objects for React Native: one per style and scheme, plain
   numbers and strings, shadows converted to native shadow props.
3. TypeScript types for token names.
4. One flat JSON per mode for Figma import.
5. A Tailwind v4 `@theme` bridge file for consumers.

  bubbles stay on solid surfaces.
- Regular glass is the default. Clear glass is only for bars over photos and
  video, with a 35% dark layer under it when the content is bright.
- The `glass` axis has three steps: `clear`, `regular`, `tinted`. Default
  `regular`. Lean to readable.
- Glass never sits on glass.
- Web: blur, saturation, a tint, an edge highlight and a shadow, which work
  in every browser. Refraction through an SVG filter on the backdrop works
  only in Chromium, so it is an opt in extra behind a prop, off by default.
- Under reduced transparency or more contrast, glass becomes a solid surface.
- Contrast is tested against the brightest and the darkest backdrop.

## 12. Accessibility, RTL and content rules (apply everywhere)

| WCAG 2.2 | Rule |
| --- | --- |
| 1.4.3 | Text at 4.5:1 on every surface it can sit on, including glass over its worst backdrop |
| 1.4.11 | Control borders, focus rings and chart marks at 3:1 |
| 1.4.4, 1.4.10 | Never block page zoom. No sideways scroll at 320px. Native text scales to 200%. |
| 1.4.13 | Tooltip component only. No native `title`. |
| 2.1.1 | Every component has a written keyboard map |
| 2.2.2, 2.3.1 | A pause control for anything that plays for more than five seconds. Nothing flashes more than three times a second. |
| 2.4.7, 2.4.11 | 2px focus ring. Sticky and floating bars reserve scroll padding. |
| 2.5.7 | Every drag and every swipe has a button or key path |
| 2.5.8 | 24px minimum targets on the web, 44px in touch templates, 44pt on iOS, 48dp on Android |
| 3.3.7, 3.3.8 | No asking twice. OTP fields allow paste and password managers. |
| 4.1.3 | Toasts and chat turns announce once |

The same criteria apply to React Native screens. Roles and states map to
VoiceOver and TalkBack through the manifest.

RTL and Arabic:

- Web: wrap the app in the direction provider through `Theme` (Radix) or
  `dsTheme` (CDK). React Native: `I18nManager`.
- Directional icons carry a mirror flag. Brand marks, clocks and media
  controls never mirror.
- Arabic text: IBM Plex Sans Arabic, zero letter spacing, taller line height,
  small text one step up. No uppercase or italics for emphasis.
- Latin runs inside Arabic go through `Bidi`.
- Western digits by default. Arabic comma in running text.
- Pixel styling stays in icons, never in Arabic text.

Copy:

- English: sentence case. Buttons are a verb plus a noun, never "OK",
  "Continue", "Confirm" or "Yes". An empty state says what to do next. Name
  the mechanism.
- Arabic demo copy: white Saudi dialect, noun form labels, no diacritics.
  Read GoBanana's `docs/arabic-copy-cookbook.md` first. The content guide in
  the docs describes two registers, Gulf modern standard Arabic and white
  Saudi dialect, and lets each product pick one.
- No em dashes or en dashes anywhere. The gate fails the build.
