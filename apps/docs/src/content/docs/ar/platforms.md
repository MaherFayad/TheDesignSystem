يعمل النظام على الويب عبر React وAngular، وعلى iOS وAndroid عبر React Native.
للمكون الاسم نفسه والخصائص نفسها والقيم نفسها على كل المنصات، ويحدد محور
`platform` وإطار العمل ما يتغير.

## محور المنصة

| القيمة | مجال التطبيق |
| --- | --- |
| `web` | المتصفحات، React وAngular، وهي القيمة الافتراضية على الويب |
| `ios` | React Native على iOS، أو شاشة ويب تحاكي iOS |
| `android` | React Native على Android، أو شاشة ويب تحاكي Android |

يضبط المحور على عنصر Theme الجذري: `<Theme platform="ios">`. يكتب Theme السمة
`data-platform` على عنصره، ولا يقرؤها المكون إلا حيث تختلف المنصات فعلا. على
الويب حاليا يقرؤها Rail، فيأخذ شكل شريط التبويب الخاص بكل منصة. في React Native
يقرأ المزود منصة الجهاز عند عدم تحديد الخاصية، وتحمل كائنات السمات مقاسات كل
منصة.

## حسب إطار العمل

| إطار العمل | الحزمة | المظهر | السلوك |
| --- | --- | --- | --- |
| React | `@the-system/react` | `@the-system/css`، مشترك مع Angular | Radix وReact Aria |
| Angular | `@the-system/angular` | ملفات CSS نفسها دون أي تغيير | Angular CDK وAngular Aria |
| React Native | `@the-system/native` | كائنات سمات مولدة ودالة أنماط لكل مكون | RN Primitives |

تعرض [صفحة التغطية](/ar/frameworks/coverage/) الجاهز في كل إطار عمل.

## الأهداف والخطوط حسب المنصة

- الأهداف: 24px على الويب (WCAG 2.2، المعيار 2.5.8)، و44px في قوالب اللمس،
  و44pt على iOS، و48dp على Android.
- يتكبر النص في التطبيقات حتى 200% مع إعداد النظام، لذا لا يثبت ارتفاع أي
  حاوية نص.
- من اليمين إلى اليسار: يتبع الويب السمة `dir` على Theme، ويتبع React Native
  الإعداد `I18nManager` ويتطلب إعادة تشغيل التطبيق بعد التغيير.
